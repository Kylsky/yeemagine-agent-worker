# 协议与架构

```text
浏览器 ── OAuth / 扫码 / 断开 ── Worker HTTP ── 唯一 ConnectionDO
                                            │ SQLite 加密状态
                                            │ alarm 长轮询、任务轮询
                                            ├── 微信 iLink API / CDN
                                            └── YeeMagine OAuth / Agent API
Cron 每 10 分钟 ── 缺失 alarm 时补建 ────────────┘
```

## 模块

- `index.js`：Worker 路由、安全响应头、DO 包装与 Cron。
- `connection.js`：认证、扫码、消息、命令、报价确认、回复进度、生命周期。
- `state.js`：SQLite 状态与自动生成的持久实例密钥；同步 SQL 写入，不跨网络事务。
- `platform.js`：固定 origin 的 OAuth / Agent 请求、限长响应。
- `weixin.js`：iLink 请求、二维码、媒体协议。只向微信 API 发送 bot token。
- `crypto.js`：随机数、HMAC、PKCE、AES-GCM。
- `commands.js`：命令与 Unicode 分段、报价和问题展示。

## 调度与恢复

每轮 alarm 只做一次微信长轮询，各环节的失败互相隔离：

| 环节 | 出错时 | 是否影响收消息 |
| --- | --- | --- |
| 核对平台身份 | 记录问题，30 秒后再核对；只有账户不符或授权失效才清除连接 | 否 |
| 微信长轮询 | 失败后 2 秒重试，连续 3 次后等 30 秒并重新计数；`-14` 暂停 1 小时 | 是（只有这一项） |
| 处理单条消息 | 暂时失败时保留游标；普通命令最多 3 次，明确拒绝立即跳过；提交结果不确定时始终保留原幂等键 | 只暂停到这条消息 |
| 查询任务进度 | 暂时失败按 2 秒起、最长 30 秒退避，保留原 runId；暂停、Secret 错误和损坏响应不释放任务；明确无权访问或不存在时告知用户去平台查看 | 否 |
| 回传任务结果 | 明确发送失败最多 5 次，之后告知用户去平台查看；已发送但回执不确定的段落不自动重发 | 否 |
| 回复用户 | 尽力发送，失败只记诊断，不重新执行命令 | 否 |

节奏与超时对齐腾讯官方插件：长轮询超时取服务端返回的 `longpolling_timeout_ms`（默认 35 秒）；扫码状态是 35 秒长轮询，超时或网络抖动视为仍在等待。

有任务在跑时，长轮询期间按 2–15 秒退避查询任务进度；查询出错也会等本轮长轮询结束再返回，同一微信账号任何时刻只有一个长轮询。每批消息有 20 秒处理预算，未全部处理时保留旧游标，下轮重新拉取并按 HMAC 去重。平台提交使用稳定幂等键；图片上传成功后只保留资源 ID 以保证提交重试的引用稳定。

提交前持久保存原会话、模型、模式、资源 ID 和消息 HMAC，不保存正文。提交结果不确定时，重放始终沿用这些参数及 `wx:<消息 HMAC>`，即使参考图期限已到或默认模型发生变化也不变更；随后遇到权限拒绝也不能证明此前未创建任务，因此保留待确认记录并阻止新生成请求。首次提交明确拒绝才释放该记录。活动任务另保留触发消息的 HMAC，避免长任务超过普通去重期限后重复提交。

平台内部压缩、交接期间快照保持 `running`，Worker 只查询原 runId，不展示中间摘要或发起新任务。终态检查 `partial` 和 `stopReason`：部分完成单独发送提示，已有文字和图片继续交付，提示不改变原正文分段序号。

访问令牌到期或返回 401 时，复用同一刷新请求并保留固定 refresh token；迟到的旧令牌 401 使用已刷新的令牌。刷新暂时失败保留原任务，只有明确授权失效才清空连接；平台暂停或 Client Secret 错误恢复后继续原任务。

扫码状态查询不经过平台，也不与生成二维码等操作共用锁；页面遇到临时错误继续查询，只有二维码过期、登录失效等情况才停止。撤销授权以清除本地数据为准，平台撤销失败时提示用户到平台再撤销。

游标在消息处理完后才保存，依赖“用旧游标能重新拉到同一批消息”。官方插件是先保存游标再处理；这一前提需要实机验证，若不成立，处理失败的消息会丢失但不会阻塞后续消息。

消息处理与平台网络 I/O 不持有 SQLite 事务。外部响应后校验连接代次；断开或重新授权后，旧任务不能覆盖新状态。已经发出的上游请求无法撤回，用户断开前应主动取消任务。

平台完成结果只在内存中读取。[Durable Object alarm 可能重复投递](https://developers.cloudflare.com/durable-objects/api/alarms/)，因此同一实例的并发交付共享一次执行，跨实例恢复依赖 SQLite 进度。结果及待确认提示按确定顺序分段发送；发出前保存发送标记，成功后保存计数。明确拒绝可以重试；回执丢失或发送后保存进度中断时，不自动重发该段，提示用户到平台查看。稳定 client_id 不能视为上游保证的去重契约，这种处理可能少送一段，但避免重复回复；不确定的报价不会启用微信文字确认。上传图片响应丢失可能留下平台孤立资源，但不会重新扣生成积分。

## 平台接口

固定根地址，无需额外 `/api` 前缀：

- GET `/oauth/authorize`、`/oauth/me`；POST `/oauth/token`、`/oauth/revoke`。
- GET `/v1/account/balance`、`/v1/agent/models`。
- POST `/v1/agent/threads`、`/v1/agent/threads/:id/messages`。
- GET `/v1/agent/runs/:id`；POST 其 `/confirmation`、`/user-input`、`/cancel`。
- POST `/v1/agent/images`；GET `/v1/agent/resources/:id/content`。

平台须实现不轮换的固定 refresh token、消息幂等键、应用级资源隔离、真实费用确认和受限 Agent 工具。Worker 不自行计算积分、不调用模型供应商、不执行模型生成的 URL 或脚本。

## 微信版本

协议按 NOTICE 固定版本实现，未来上游更改需要重新核验。QR scan 查询支持 need_verifycode、scaned_but_redirect、confirmed 等状态；binded_redirect 不凭空恢复凭证，要求重新扫码。

上下文 token 来自收件消息，缺失时不尝试主动群发。仅接受已绑定 owner 的完成态用户私聊消息。图片最大 8 MiB，网络响应实行流式计数上限。当前未实现微信 typing 或 lifecycle 通知；对话以立即确认消息提示处理状态。
